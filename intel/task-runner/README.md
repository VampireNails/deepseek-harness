# Linux task runner

English | [中文](README.zh.md)

Final task failures emit `task.failed` with the JobLog run ID, safe code and exit category. Event write errors are independently reported to stderr and the route audit, preserving the task's nonzero exit. A successful task is never relabeled failed by an event or JobLog write error. A real lock timeout emits `runner.lock_timeout` without creating a completed task run. Routes config `lockTimeoutSeconds` accepts 1–610 seconds and defaults to 610; a private acquisition marker distinguishes flock conflict exit 75 from task exit 75. Quiet upkeep admission/backoff and successful tasks emit no failure event. See [system events](../../intel-plugins/dsh-intelligence-sysevents/README.md) for isolation, deduplication and source recovery.

The ChatGPT cron route explicitly uses SSE for each one-shot process. The installed SDK's default WebSocket cache otherwise retains the process for five minutes after a reply. This per-invocation patch leaves the web profile unchanged. Route `transport` accepts `sse`, `websocket`, `websocket-cached` or `auto`; fallback requests use their own route's transport.

This runner resolves built-in cron task IDs against the live evolution `TASKS` templates. An optional old prompt is ignored for built-in IDs; custom jobs require their explicit prompt. `routes.json` supplies task routes, the default provider/model and timeout. The runner launches only the `evolve` DSH profile, with an explicit model patch. It requires installed profile dependencies and normal provider credentials; it does not install providers or image tools.

`route-runs.jsonl` records requested provider/model, template ID, process exits and fallback reasons without prompts or credentials. Requested identity does not prove the effective model: correlate successful requests with tokenlog. Retrying a nonzero exit may duplicate side effects, so default routes disable retries. Enable `retrySafe` only for an audited read-only task. Timeout terminates the process group; an exit failure can still mean partial effects and requires review.

JobLog completion carries the same run ID and start time as the route audit, with final exit and an audit-file reference. `INTEL_JOBLOG_SCOPE=test` explicitly isolates controlled tests; absence selects production and other values reject. A JobLog persistence error exits nonzero and is audited by safe code, without creating a second failed run for an already completed task. See [JobLog](../../intel-plugins/dsh-intelligence-joblog/README.md) for retention, partial persistence, old snapshots and backup requirements.

The nine deployed task assignments omit `fallback`: a primary failure is final and retains its requested route and exit in the audit. An explicitly audited read-only custom task may configure both `fallback` and `retrySafe: true`; its fallback attempt records its own provider, model and transport. Configuring only `fallback` does not authorize a retry.

Tasks with `visibleOutput: "required"` need a persisted Feed post or Artifact version from their own run. The runner's final dreaming prompt requires Feed publication and preserves the template's prohibition on `artifact_save`; other templates retain the optional long-report guidance. A process exit of zero without readable output becomes exit 65, including fallback attempts, and is never retried. The runner supplies task ID, unique run ID and date in the configured timezone to the publishing tools. `references` accepts existing integer memory IDs, validated before writing. Manual publications have no invented run identity. Optional upkeep remains successful without publishing when it finds no signal.

Referenced publications retain the configured memory directory, so output inspection reads the same database even with a custom memory `dataDir`. The evolution plugin records newly created root sessions in `intel-joblog/automation-sessions.sqlite` under the shared DSH home, using the runner identity. It excludes canonical subagents and ordinary sessions, preserves session headers and never infers automation from workspace paths or prompt fragments. Readers open this index read-only; missing history remains unclassified.

[Legacy attribution](legacy-session-origin.mjs) is offline maintenance over trusted private observations. Only a complete first genuine user message matching an exact historical task template, both header and message timestamps inside one paired audit interval, and a one-to-one root/interval match qualify. `dry-run --index /absolute/index.sqlite` reads observations from stdin and prints hashes; `apply` additionally requires an unused absolute `--backup` path. Synthetic `legacy-evidence:` run IDs distinguish migration evidence from native runner IDs. Conflicting attribution aborts the entire batch. `rollback` takes the anonymous apply receipt and removes only inserted rows whose complete identity still matches, preserving later native records. The caller must extract and verify the original logs; the CLI does not authenticate arbitrary supplied observations or classify unknown history.

`deduplicateDaily: true` checks persisted task/date output before execution and records `already-published` with its original run ID. Linux `flock` serializes each task across this check, execution and final audit; different tasks remain independent. Feed and Artifact stores also serialize writes and reject conflicting reuse of a publication key. Feed displays the latest 100 posts and retains publication identities in `.publication-history.sqlite`; Artifact versions retain their individual run identities and memory references.

Back up the complete `intel-feed` and `intel-artifacts` directories while writers are stopped, including hidden SQLite files. Preserve `.publication-history.sqlite` when restoring or changing versions: deleting it loses duplicate protection for posts outside the display window. Stop cron runners before switching to an older writer, since older versions do not participate in these locks. A failed run may already have persisted output; inspect the audit and output before any manual retry.

Before deployment, back up `crontab -l`, then pipe it to `node intel/task-runner/cli.mjs --migrate-crontab` and compare the preview. This command prints a replacement but never writes crontab. It migrates only registered built-in jobs with a single quoted literal prompt; custom jobs, compound commands, redirects and environment-specific wrappers stay unchanged for manual review. After review, deploy `run.sh` with executable permission, preserve cron schedules/timezones and inspect the first run. Do not blindly rerun a failed task. Existing profile configuration and production cron are not changed by adding this directory.

Run `node --test intel/task-runner/tests/*.test.mjs` on Linux. Isolated CLI tests use a fake `dsh` executable and never invoke production models.

`routes.json.heartbeat.enabled` enables bounded local preflight; missing configuration or `false` retains legacy dispatch. An existing empty checklist opts out with `heartbeat-empty-checklist`; a missing, unreadable or unfamiliar nonempty checklist fails. The supported [checklist](../../intel-plugins/dsh-intelligence-evolution/HEARTBEAT.md) maps to service state/restarts, the exact HMC listener, disk and memory thresholds, complete recent journal error records, and JobLog/route history. Source reads never launch a model or write source data. Unknown, truncated, corrupt or denied input fails with its original safe code through the runner's failure event; no result is inferred from prompt words. Recent legacy starts without run IDs remain unverified; selected route, JobLog and alert timestamps later than the observation cutoff fail without clock-skew tolerance. Older source labels remain unclassified, explicit test rows stay excluded, and heartbeat's own failures belong to its pending checkpoint to prevent feedback loops.

Heartbeat configuration requires `serviceUnit`, `listenAddress`, `listenPort`, `minDiskBytes`, `minMemoryBytes`, `sourceTimeoutMs`, `maxSourceBytes`, `windowMs`, `pendingAfterMs`, `initialBackoffMs` and `maxBackoffMs`. The shipped settings use 5-second probe deadlines, 4 MiB per file/command, a one-hour error window, a 700-second unfinished-run threshold, 2 GiB disk and 100 MiB memory thresholds, and one- to four-hour repeated-anomaly backoff. Every invocation captures all current sources before checking backoff. Stable healthy threshold results launch zero models; a changed signal, recovery or due repeated anomaly admits one run. Available resource fluctuations within healthy thresholds do not change identity. Source/config changes reset backoff; a same-anomaly backward clock fails visibly, while a changed signal still admits and retains a monotonic deadline.

The heartbeat flock covers preflight, admission, dispatch and audit. Production uses `intel-joblog/heartbeat/state.json`; explicit test scope has a separate lock and `test-state.json`. The runner fsyncs pending signal/run IDs before launch and clears pending only after process success and a durable completion checkpoint. Failure, crash or uncertain completion refuses identical redispatch across restarts. A new reliable signal may supersede pending, retaining the previous identity in the audit without replaying its effects. Preserve state through upgrades; inspect the original run and system events before manual correction. Quiet decisions record reason, hashed checklist/signal/source identities, observation time and zero executions; they create no successful model JobLog run or anomaly notification. Admitted summaries contain status and safe event identities rather than journal messages or prompts and enter the profile's logged task input. Process success does not establish model/tool outcome verification or notification delivery.

Both upkeep aliases share a `memory-upkeep` flock and private `intel-joblog/upkeep/state.json`. The first invocation checkpoints existing raw session cuts without launching a model or treating history as new input. Later invocations consume new original user-channel messages with [Host authorship labels](../../intel-plugins/dsh-intelligence-evolution/README.md#understand-the-implementation); indexed automation and canonical subagents are excluded. Missing labels from older source servers remain unknown, while invalid labels or machine messages reject the source batch before dispatch. Same-time messages are distinguished by their raw event sequence. Full messages must fit the configured batch limits; an oversized original or an unavailable source fails without advancing its checkpoint.

`routes.json.upkeep` supplies the existing Host's owner-only `socketPath`, its `sourceTimeoutMs`, batch limits, and initial/maximum backoff milliseconds. The production defaults admit 12 messages and 24,000 characters, with one-, two- and four-hour empty-work backoff. Skipped backoff invocations do not query sessions or launch a model. New input becomes discoverable at the next due invocation, rather than resetting the deadline immediately. A backward clock leaves checkpoints unchanged. The [evolution plugin](../../intel-plugins/dsh-intelligence-evolution/README.md) owns the source configuration and raw read limits.

Before a nonempty batch launches, the runner fsyncs its pending run identity, hash and proposed cursors. It patches upkeep tools to native mode and sends the original batch through the profile's logged task input. Checkpoints advance only after process success and persisted completed-turn/tool-result inspection of that exact run. A completed turn with no useful memory may commit without a write. Missing completion, denied tools, failed writes or an uncertain process leave the pending batch intact. Later invocations inspect the original alias and run; they never redispatch pending side effects. Unresolved pending runs require operator review. Preserve the private state file through upgrades and inspect actual logs/memory writes before any manual correction; deleting state can lose unacknowledged input.

The production route assignments are preserved: upkeep and heartbeat use Flash; morning briefing and the other six evolution jobs use ChatGPT. `bash intel/verify-linux.sh` installs each plugin's locked dependencies and runs the Linux plugin/runner regressions; run it in a disposable checkout because it replaces plugin dependency directories.
