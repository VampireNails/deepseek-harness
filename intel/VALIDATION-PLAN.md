# 智能体能力验证计划

本参考文档定义 Linux Muse 的证据要求。HMC 客户端验收只针对 Android。负责角色表示执行责任，不代表已向其他人派发任务。

| 项目 | 负责角色 | 时间（Asia/Shanghai） | 执行与通过判据 |
|---|---|---|---|
| 多模型路由 | Muse 维护者 | 发布当日 | 逐个提供方获取非空目录，再对目录中两个不同提供方的模型各执行一条受控只读请求；记录 task ID、请求/实际 provider+model、成功响应、回退原因。目录本身不算成功调用。覆盖已配置任务、未知任务、提供方失败回退；禁止把未配置 test_* 默认 flash 当作多模型故障。 |
| 对比任务 | Muse 维护者 | 2026-10-05 至 10-11 | 固定 10 个只读任务及相同输入，分别执行两侧；提前定完成度、事实错误、引用、耗时和费用评分。保留匿名产物；失败不得从样本中删除。 |
| 30 天任务可靠性 | Muse 维护者 | 2026-10-05 至 11-03，11-04 汇总 | 按计划触发次数作分母，区分成功、失败、超时、未启动、结果不明及主动跳过；按 task ID 保存逐次结果。job_runs.json 只有最后一次状态，不能用于 30 天成功率。收集生产 cron 时区并换算；缺失记录计结果不明。 |
| 条件主动性 | Muse 维护者 | 发布当日及每周 | 隔离环境注入确定异常和确定正常样本，验证应触发与应安静两条路径；不得在生产制造故障。零触发本身不证明正常。 |
| 记忆与旧任务模板 | Muse 维护者 | 模板发布当日 | 内置 task ID 在运行时读 TASKS；自定义任务保留显式 prompt。系统 crontab 与插件 CronStore 分别盘点，先备份和 dry-run，不重建已运行或有副作用的任务。检查 upkeep 模板及 dreaming 失败复盘要求。 |
| 用户盲测 | 用户，维护者准备样本 | 2026-10-12 起 | 用户自愿评分至少 10 对匿名产物，记录偏好和理由；参与者与样本不足时标为待验证，不宣称超越。 |
| Android 展示 | HMC 维护者 | 客户端发布当日 | API 33 测试上下文折叠/原文、权限目录/错误、joblog 直读和工具预览；真机 HTML 截图使用无私有数据的样本，单列模拟器与真机证据。 |

图片生成维持未复刻范围；只有注册工具、挂载 profile、调用真实生成模型并能查看产物才算完成。后台监控是用户启用的单会话有限时提醒；未启用时不能承诺审批推送。

intel push 的 Linux 专项检查覆盖插件语法、插件回归及部署脚本语法；上游 PR CI 仍承担其原有检查，不以 Windows/Mac 结果作为本交付验收。
