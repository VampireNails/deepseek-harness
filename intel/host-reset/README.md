# HMC full deployment reset

English | [中文](README.zh.md)

This opt-in Linux management service runs outside the DSH service cgroup. It accepts no client paths or shell commands. HMC exposes authenticated preparation; the separate operation TLS channel admits commit only after Android durably stores and verifies the operation connection. No business data or credentials are backed up.

Install as root with `python3 intel/host-reset/install.py --config /private/manifest.json`. The root-owned mode-0600 manifest specifies `home`, `deploymentRoot`, `protectedRoots`, `credentialFiles`, `profileManifest`, `service`, `firstUseOverride`, `webPort`, `trustedHost`, `cronCommands`, `runnerEntrypoints`, `stateRoot`, `socket`, `progressHost` (IPv4), and `progressPort`. The installer allocates a deployment UUID and retains it across upgrades. The socket is `/run/hmc-host-reset/control.sock`; the control state must be outside every erased directory. HMC detects the root-private socket; unavailable installations advertise no reset capability.

The default web profile manifest contains installed bundles without model credentials, personal patches, the credential-dependent intelligence guard, or the HMC transport. Reset preserves the installed `web/node_modules`, dependency lock files, HMC wrapper code, source repositories, and infrastructure. It removes all other DSH home and HMC deployment state, the listed credential files, and exact owned cron command tokens. It freezes and terminates runner descendants and tagged detached tasks, stops the main service, and refuses deletion while another process has a writable file descriptor in the erased roots. It then starts the supported `dsh --profile web` in explicit first-use mode. Reconfiguring protected production startup and new HMC pairing remains an administrator action after reset.

Preparation is idempotent by UUID and globally exclusive. Commit has a 15-minute admission window; restart never automatically commits prepared operations or replays an interrupted worker. A failed reset retains its operation record and Android data for administrator diagnosis. Completed TLS proof remains available until the client acknowledges its durable receipt. Acknowledgement retires the newly generated TLS credentials; it does not retain deleted user data. An administrator must inspect and resolve failed operations before admitting another operation.

Run Linux checks with `python3 -m unittest discover -s intel/host-reset/tests -v`. Android clear-data terminates its process, so final-device proof is collected externally using ADB and first-use startup inspection.
