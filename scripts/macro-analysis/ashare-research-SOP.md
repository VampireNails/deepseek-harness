## 二、数据口径纪律（红线，违反即全部结论作废）

1. **5 年以上日线回测一律后复权（hfq），禁用前复权（fqt=1）**。前复权以最新价向前扣分红，
   长周期必然出现负价格（002714 牧原 506 日 ≤0.5 元、最低 −3.60 元），是**股票级缺陷，截断区间救不了**。
2. **三条复权捷径均已证伪，别再试**：① `badj = adj + 常数`（000798 差值 3.36~13.01）；② raw+adj 反解（推出恒等式，误差 37%）；③ 东财 `pct_chg`（= close/prev−1，未除权，除权日 002714 = −51.61%）。
3. **A 股后复权唯一可用源：腾讯 fqkline hfq**。六个坑已固化进 `ashare_badj_collect.py`：
   ① 单请求硬上限 **641 根**（超限返 `param error`）→ 分段抓取；
   ② **★ 开放末段窗口静默截头（比①更险恶）**：分段窗口写死开放终点（如 `("2024-01-01","2026-12-31")`）会随日期增长，超过 641 根后腾讯**不报错，静默截掉响应头部** → 该窗口内所有股票缺同一批 bar（实测 2024-01-02~01-10），脚本自带 QC 容差放过。**分段窗口必须动态生成**（`build_chunks()` 固定 548 天/段 ≈370 根）+ 行数 ≥630 告警；存量库须做缺口扫描（对照交易日历/分段头部窗口）；
   ③ **域名级封锁**：`web.ifzq.gtimg.cn` 批量约 450 次后返 HTTP 501，`ifzq.gtimg.cn` 与 `proxy.finance.qq.com` 仍 200 → 多域名候选自动切换；
   ④ 返回键名是 **`hfqday`**（不是 `hfq`），`data` 出错时是 list，需 `isinstance` 容错；
   ⑤ **次新股空分段**：晚于起始年上市的股票早期分段返回 `{"day":[],"qt":{...}}` 无 hfqday 键——空数组是正常，用 `rows is None` 判空，当致命错误会误弃整只股票；
   ⑥ **股票级 hfq 缺失**：个别股票请求 hfq 却返回**未复权 `day` 键**（实测 688981 中芯国际，三域名一致）→ fail-closed 只读 hfqday 会正确拒绝，该股票剔除出池并登记（类似北交所剔除先例）。**别手动改代码容忍 `day` 键——那是未复权数据，污染即作废。**
4. 腾讯 hfq **只返回成交量（手）**，无成交额/换手率 → amihud/换手率因子必须 LEFT JOIN 东财流动性表（`daily_liquidity`，按 `(code, trade_date)`）。
5. **涨跌停分板块**：主板 ±10% / 创业板(300,301)、科创板(688) ±20% / 北交所(920,430,83,87,92) ±30%。
   后复权日收益落在限内本身就是**强校验**（超限 = 复权因子有误，如 600540）。
6. **北交所 + B 股必剔除**（腾讯无北交所 hfq；B 股流动性不足）。
7. **A 股不可做空**（农业融资券源近乎为零）→ 主口径 = 纯多头 Q5（或 Q1）相对池内等权基准的**扣成本超额**，多空仅作参考列。
8. **费率三档（往返）**：0.30 / 0.50 / 0.80%（印花税 0.05% 卖出单边 + 过户费 0.002% + 佣金 0.05% + 滑点）。

## 三、验证框架：三关 + MC + 四级结论分类

**第①关（功效）**：σ_true 与 MDE。判据 |效应|/MDE ≥ 1。MDE 用 `Var_noise ≈ 1/(N−1)` 口径，
**N_eff 按独立观测算，不按报告期数**（A 股披露高度集中：年报 4/20 与一季报 4/28 仅隔 2~4 交易日，
按"未来 60 日收益不重叠"去重后每年仅 2 个独立观测 → N_eff=26 而非 50，MDE 从 0.055 抬到 0.088）。
**任何按"报告期数"估 N_eff 的做法都系统性高估功效。**

**第②关（显著性）**：IC 主判定 Newey-West HAC（lags = 持有期−1）；低频用 `period_level_ic`（Fama-MacBeth）；
MCC 多重比较校正。**MCC 会高估独立检验数**（因子高度冗余时 n_tests 虚高）——显著性只测"与收益相关"，
**不测"是否独立于已知风格"**（那要靠第③关后的正交化）。

**第③关（经济可行）**：回测四项全满足才通过——中成本超额>0 **且** IR≥0.50 **且** 分年度为正≥2/3 **且** 五分位严格单调。
**前提是数据口径正确**（前复权污染曾把第③关打成假 0/28）。

**MC 零分布检验（跨池通用，可复用）**：用同一回测引擎构造零分布，绕开 IC t 统计的所有分布假设。
- **random 口径**：AR(1) 随机信号，**必须校准换手率**（iid 随机会跑到 8.0x vs 真实 5.4x，成本凭空多 1.3pp → 虚假显著）。二分校准 rho。
- **shift 口径（主判据）**：股票维度**全局置换**（保留信号时序与换手结构，只打乱配对）。
  **绝不能每期独立置换**——持仓每期全变、换手暴涨、零分布人为负偏。
- **自校验**：零分布年化均值 ≈ −(换手 × 费率)（实测 −2.65% ≈ 5.3x × 0.5% ✓）。

**四级结论分类（不得混淆）**：

| 类型 | 判据 |
|---|---|
| 信息性零结果 | 不显著 + 功效充足 |
| 功效不足 | 不显著 + 功效不足 |
| 疑似夸大 | 显著但观测 < MDE |
| **真实但不可交付** | 显著 + 但归因是风险暴露 / 参数子样本不稳 / 经济上不可行（超额集中极少年份、幸存者偏差量级相当） |

## 四、归因方法论（正交化，别用回归截距 α）

- **⚠️ 回归截距 α 不可用作归因**：分位数组合构造上带大倾斜（实测 Q5 带 −1.04σ 换手、−0.92σ 动量），
  样本内无零暴露观测点 → α 是样本外 extrapolation（实测给过 −257%~+1161% 的荒谬值）。
- **正确做法：逐期把 signal 对风格 z 做截面回归取残差，用残差信号重跑回测，比较超额衰减。**
  完全样本内、不外推。双口径：`orth_resid`（只对未交易特征正交，主判据，避免循环论证）与
  `orth_all`（全部正交，极端破坏性测试，仅作上限）。
- **必须配 drop-1 稳健性**：一次只剔单个风格，保留率无一归零才能排除方法 artifact。
- **R²(信号落在风格空间) 最直观**：R²≈0.7 ⇒ 信号七成只是风格的线性组合。
- 实战判例：农业价量 7/7 策略正交化后超额全转负（100% 风格押注）→ **换任何价量因子都无意义**；
  A 股基本面「净利同比」正交化后保留 59% IC、t=−3.16 → **是独立信息**（本项目唯一）。
- **★ 换池前先判：信号是「风格马甲」还是「独立信息」。前者换池没用，后者换池才可能救活。**

1. **缓冲带（换手抑制）默认开启**：买入 top 20% / 卖出门槛外扩至 top 35%。实测 140 组合 89% 改善、
   中位数 +2.55pp、换手降 30~75%、毛超额只衰减 0.54pp（≈纯机械省成本）。**不做每期全换。**
2. **可交易掩码只能有一处构造**：`ashare_agri_backtest.build_tradable()`（剔 B 股 + volume>0 + 20日均额>0 + QC 黑名单）。

   这类 bug 极隐蔽：跑得通、数字还更好看。
3. 分年度检验 + 剔除最强势期检验是标配；剔除最优 2 年后塌掉的超额 = 集中度风险。

## 六、静默 bug 六类高发形态（一轮内全踩过，全不崩溃、全输出"正常"数字）

1. **去重键用错**：(report_date, 生效日) 元组去重 → 同一报告期拆成几十个"期"，N_eff 严重低估。**去重键只用逻辑主键。**
2. **多因子联合缺失 → 整行丢弃**：正交化观测 25 暴跌到 8。改为缺失填 0（z 已标准化，0 即中性）。
3. **★ 方向性判据写反**：信号已取负号，单调性方向写反 → 会把实际单调的因子误判成不单调。**改变结论。**
4. **★ 缩进错误让代码块掉出循环**：只对最后一个因子执行，前两个结果静默缺失。**改变结论。**
5. **敏感性参数化错误**："每期退市 k 只"实为全样本 26 只，夸大 26 倍。参数必须对齐现实可观测口径。
6. **同名函数返回值不同**：两版 `newey_west_t` 返回 `(t,n)` vs `(mu,se,t)`。按来源分别解包，别猜。

**共性防线：把中间量打印出来交叉校验（观测数、覆盖率、单调序列、分量之和）。只看最终数字一个都抓不到。**

## 六·补、第七类静默 bug：统计量公式本身写错（2026-09-03 宏观线踩到）

7. **★ 检验统计量公式错误**：`dm_test` 写成 `se=sqrt((1/n+1)*gamma0)`，正确是 `se=sqrt(gamma0/n)`
   → 统计量被系统性低估 **√(n+1) 倍**（n=6 时 2.65 倍，n=283 时 **16.85 倍**）。
   不崩溃、不报错、输出"正常"的小 t 值与大 p 值，直接把三个结论误判成"功效不足"。
   **防御：任何检验实现后，用一个人手可算的小算例反推量级**（如 n=100、dbar 已知、γ₀ 已知时手算 stat），
   并断言数量级合理。本类 bug 比前六类更危险：它让所有结论**统一偏向"无效应"**，看起来还特别"严谨"。

## 六·补二、第八类：源字段语义误读（2026-09-03 宏观线踩到）

8. **★ 把"期始日"当成"发布日"**：eastmoney `REPORT_DATE` 是期始日
   （TIME=`2026年08月份` → REPORT_DATE=`2026-08-01`，而 PMI 实际发布在 8/31）。
   写入 `release_date` 后会让**所有 as-of 发布日过滤产生系统性前视**。
   **防御：新接入源的每个"看起来像日期"的字段，必须用一条已知发布时间的样本反查语义；语义不明就置 NULL，绝不猜。**

## 十一、运行坑速查

- `| head -N` 会 SIGPIPE 杀 python → 一律重定向到日志文件。
- **重定向到文件时 stdout 是块缓冲**：长跑采集日志会落后实际进度（8KB 缓冲 ≈ 110 行 ≈ 13 分钟无输出）。判断"卡死"先看三件：① 日志 mtime 是否仍在推进；② 进程是否存活/CPU 是否变化；③ 按吞吐率估算 ETA。勿凭日志尾部不动就杀进程。
- `wc -l` 对**无尾换行的单行文件**少计 1（逗号分隔 codes 清单核对数量用 python `len(split(','))`，别用 wc）。
- verdict 值 `"★ 通过"`/`"     未通过"` → 统计用 `x.startswith('★')`，勿用 `'通过' in x`。
- `VACUUM INTO` 产物可能被沙箱 FS 守护拦截（connect 报 unable to open）→ 直接在主库分析。
- 路径层级：`_HERE = Path(__file__).resolve().parent; ROOT = _HERE.parents[3]`（产物一律 `ROOT/outputs/YYYY-MM-DD/`）。

### 12.1 数据层：vintage 与权威度

  **第三方源不得因"采集时间更新"覆盖官方一手**。冲突单列 `cross_source_conflict`，

### 12.2 验证框架硬要求

- **zero look-ahead**：目标 Y(t) 只用 `period ≤ t−1` 观测；lead 项 lag ≥ 1；
  **标准化统计量（mu/sd）只从训练窗估计**；滞后用**日历算术 + as-of 回填**
  （位置索引 `grid[ti−L]` 在序列有缺口时不是日历 t−1；季度序列也由此对齐）。
- **基线**：persistence（y(t−1)）为主；同时报 mean 与 drift。
  注意 persistence 不总是最优基线——非农 mean 基线 RMSE 1302 优于 persistence 1812。
- **显著性双闸门（必须同时过）**：
  ① **Clark-West (2007)** —— persistence 是 ridge 的**嵌套特例**（ridge 含 y(t−1)），
     DM 对嵌套备择有偏，须用 CW；
  ② **Newey-West 稳健 DM**（lag=3）—— 因 **CW 会被"预测方差大"的狂野模型骗到**
     （实测 PMI post2015：降幅 −20.98% 却 CW p=0.0115）。缺任一条不得判显著。
- **SOP 三件套**：MDE(80%) + 效应量(RMSE 降幅%) + \|效应\|/MDE ≥ 1。
- **★ 逐年一致性为可交付硬门槛**：逐年为正 **< 60% 即判不可交付**。
  本轮凭此把 PPI（15/18）与 PMI（7/16）分开——与 A 股"超额集中在 2018+2021"同源，
  但宏观可按自然年直接量化，更好用。
- **regime 子样本**（full / post2015 / post2020）+ **滚动窗**（60 月）+ **缩尾** 三重稳健性。
- **★ 缩尾分位必须相对于 n**：n=241 时单点极端位于 0.4% 分位，**1% 缩尾根本切不到它** →
  稳健性检查变成假动作。用 `k/n` 估算极端点分位后再定缩尾水平。
- **必打诊断**：训练系数（判断 AR 是否爆炸：lag1 斜率 > 1 即爆炸）+ 最大误差期 Top5。

### 12.7 ★ 第十一类静默 bug：流程伪振幅（本轮最有价值的产出）

**现象**：主口径 IC 序列 sd=0.2428，是随机排序理论值 0.1187 的 2.0 倍。
第一反应（错的）：预检模型 `Var_noise=1/(K−1)` 失效、行业收益同源导致 K_eff << K。

**诊断推翻该解释**：随机**因子**跑 IC，实测 sd=**0.1213** ≈ 理论 0.1187（1.0×）
⇒ 1/(K−1) 是对的。

**负向测试定位真凶**：用**纯随机 x**（iid）跑完整流程 → IC sd=**0.2028**（1.71× 理论）。
真实 x 的 0.2428 仅比随机的 0.2028 高 20% ⇒ "高振幅"几乎全是流程产物。
机制：β_i 由历史 (x_s, y_{i,s}) 估计，与 y 的横截面结构耦合
（实测 `corr(β_i, 行业历史月均收益)=0.22~0.38`，理论应为 0）⇒ 因子混入"行业历史收益水平"代理。
**后果**：σ_obs 抬高 1.7× ⇒ MDE 从 ~0.032 推到 0.063 ⇒ 正好吃掉检出 0.04 量级效应的能力。

**修复**：样本分割（β 在分割点前估一次并冻结，检验期不参与 β 估计）
→ σ_obs 0.2428→0.1501，与理论噪声之比 1.96→1.18，放大消除。

**通律**：
1. **凡是"参数由历史 y 估计、因子又作用于 y"的规格，必须做纯随机 x 的负向测试**，
   判据：`随机 x 下 IC 的 sd ≈ sqrt(1/(K−1))`。
2. **circular shift 不能替代该测试** —— roll 残留真实对齐（实测零分布隐含 IC sd≈0.20，
   介于 0.12 与 0.24 之间），不干净。
3. **相关结构 ≠ 噪声方差**：平均相关系数 0.472、PCA 有效维度 3.7 看着"只有 4 个独立方向"，
   但随机排序 IC 方差仍严格 ≈ 1/(K−1)。**不得用相关结构去修正 Var_noise**（两者是不同的量）。

同族：方向性判据写反、QC 容差 1.15、交付层子串判定、个股级 hfq 数值错误。

### 12.8 功效预检的顺序纪律与口径 A 的杠杆

- **先定门槛，再找数据**：不要"找到什么数据就用什么"——那会在采集完之后才发现测不出
  （半截工程高发路径）。`macro_sector_timing.py` 支持 `--mode preflight` 的配置矩阵与门槛反解。
- 口径 A 的**唯一杠杆是 K**（Var_noise≈1/(K−1)，扩截面直接降 MDE）：
  N=152 时中性效应 0.04 需 **K≥35**、悲观 0.02 需 **K≥135**。
  ⇒ **申万一级（31）不够，必须用二级（≥100）**。

> ⇒ **门禁 = 数据齐备性**（判"数据够不够"）；**池归属降级为参照系清单**（判"有哪些对照可用"）。

**门禁（fail-loud）**：`data_readiness_gate(code)` → `READY` / `PARTIAL` / `BLOCKED`，
每项给 `status` + `blocks`（阻塞了哪些分析）+ `remedy`（怎么补，可执行）。

| 检查项 | 判定 | 缺失时的处置 |
|---|---|---|
| 后复权日线 | ≥250 根 OK；<250 PARTIAL；**0 根 ⇒ BLOCKED** | 年频分析受限 / **先补采再继续** |
| 财报 | 本地有 OK；本地空 PARTIAL | 走东财 API 实时拉，须标注「非本地库」、期数按实际返回 |
| 另类数据 | 任一子项 0 条 | 标注「采集未覆盖」，**不得**读成「无风险」 |

**参照系清单（非门禁）**：`coverage_preflight()` → `reference_frames` / `missing_frames`

| tier | 判据 | 额外可用的对照 | 实例 |
|---|---|---|---|
| A `POOL_STRATEGY` | 池内有可交付策略 | 池内分位排序（**非个股买卖信号**） | — |
| B `RISK_OVERLAY` | 池内有风控 overlay | 是否落入回避清单 | 000876（农业池） |
| C `IN_POOL_ALL_FAILED` | 在池内但策略全部证伪 | 无 | 600519（中证800，`csi800_np_yoy` 已证伪） |
| D `OUT_OF_POOL` | 未命中任何已建池（≈82%） | 无池级对照，**分析范围不减** | **600416（三池全未命中）** |
| E `NO_STRATEGY_FOR_POOL` | 在池内但该池无策略 | 无 | — |

**必须同时讲清的原理性限制**：已验证策略全部是**池级截面排序器**，输出「在某池内排第几分位」；
单一样本无法构成排序 ⇒ 对单只股票**在数学上无定义**。

> **纪律**：「命中池」≠ 得到个股买卖信号；「没命中池」≠ 策略对它失效。
> 池未覆盖与策略失效是两件事，必须分开陈述，不许混为一谈。
>
> **三条新增硬约束（0907）**：
> 1. **禁止**把「未命中 / 无覆盖 / 仅描述性」写进报告摘要或主结论——它属流程状态，不是研究发现。
> 2. 「不产买卖信号」是**终态裁定**，对任何股票恒定成立，**不是** `TIER_D` 的惩罚或降档。
> 3. 缺池级对照时应**主动换参照系**（申万行业 / 中证全指 / 同市值区间），不得停在「没有」。

### 13.1 第二道工序是数据质量判决（在数据齐备性门禁之后）

后复权序列的日收益**必然**落在涨跌停限内。越界即数据源异常，不是市场事实。
**必做交叉校验：未复权 vs 后复权同段对照** —— 只有未复权能告诉你真实的日收益。

### 13.2 ★ 第九类静默 bug：个股级 hfq 数值错误（600416 案例）

- **现象**：腾讯 hfq 对**部分个股**注入标准差 ~0.26%/日的噪声。序列连续、无缺失、
  无报错、肉眼完全不可见；复权因子在 36% 的交易日发生 >0.3% 跳变（正常应只在除权日跳变）。
- **证据**：2020-02 连续涨停段，未复权日收益是教科书级 +10.02%/+10.04%/+10.01%/…，

- **非通病**：同口径检验 6 只，仅 600416 异常（600519/000001/601398/000651 全部干净）。

  600416 是**数值错误**（必须靠涨跌停强校验才能发现）。

  vs 真实波动 50%，对波动率贡献仅 +0.17%）。
- **登记**：遇一例记一例，写入策略库 `stock_diag` 与本报告，不做全局假设。

### 13.3 ★ 第八类静默 bug 复现：QC 容差 1.15 再次掩盖问题

`ashare_badj_collect.py::qc()` 原判据 `|r| > lim * 1.15`（主板 11.5%）。
但 A 股涨停价 = `round(prev_close * (1+lim), 2)`，**分位舍入带来的相对误差 < 0.1pp**，
合法日收益上限 ≈ `lim + 0.005`。⇒ 容差 1.15 **放过 10%~11.5% 区间的全部异常日**
（600416 实测：报 10 天，实则 40 天）。

**已于 2026-09-03 修正为 `tol = lim + 0.005`**，并用 600416/600519/300750/000651 四只验证：
异常股从 10 → 40 天正确抓出，创业板（±20%）不再误报。

> 这是 SOP 已记录「容差 1.15 掩盖 641 截断」的**第二次复现**。
> 教训的一般形式：**任何"留点余量"的容差，都必须能从机制上论证其上界，不能凭直觉给。**

#### 13.4.1 ★ 第十二类静默 bug：字段名与语义背离（2026-09-03 湘电股份验证时发现）

`stock_diagnose.py::hfq_quality()` 返回的 `ok` **原为硬编码 `True`**（只要样本量够），
真实语义是「算出了统计量」；而真正的判决在 `verdict` 字段。

- **为什么长期没被发现**：stdout 只打印 `verdict`（人看控制台一切正常）；
  `ok` 仅用于控制「是否打印偏差统计」——那里要的正是「算出来了」的含义，局部用法完全自洽。
- **危害**：JSON 消费方（agent / 下游）看到 `ok: true` 与 `verdict: "FAIL"` 并存，
  按直觉取 `ok` 就会**把数据质量判死的股票当成通过**。600416 实测即 `ok=true, verdict=FAIL`。
- **处置**：拆为 `computed`（能否算出）与 `ok`（= `verdict=="PASS"`），打印处改用 `computed`。
  FAIL 时**更**需要打印偏差数字，不能因 `ok=False` 而省略。
- **通律**：**布尔字段名必须能通过"字面语义"测试**——若 `ok=True` 的同时 `verdict=FAIL`，
  说明名字在说谎。命名前先枚举取值组合做一次负向读法。

#### 13.4.2 ★ 第十三类静默 bug：错误实现被补丁掩盖，标签仍声称原实现

`stock_diagnose.py::beta_alpha()` 声称做 Newey-West(L=3)，实际只做了 HC 异方差稳健。

- **根因链**（agent 只看到表层「NW 是死代码」，人工核实到根因）：
  1. `u = X[:, 1:] * resid[:, None]` —— 切片丢掉常数项列，`u` 只剩 1 列；
  2. ⇒ `S`/`G` 退化为 **1×1**，无法与 2×2 的 `(X'X)⁻¹` 相乘；
  3. ⇒ 作者写下 `V = XtX_inv @ (S.sum() * 0 + HC) @ XtX_inv` —— **把 S 求和成标量再乘 0 消掉**，
     掩盖维度崩溃；注释「保守：仅异方差稳健」使其看起来像有意的设计选择。
  4. ⇒ 字段仍叫 `t_alpha_nw`，**标签与实现不符**。
- **为何危险**：本例 `t_nw=0.004532` vs `t_hc=0.004822` 都≈0，结论不变；
  但 NW 的 se 比 HC 大 **6.4%**，**在 t≈1.9~2.1 的边界区间足以翻转显著性判定**。
- **处置**：`u = X * resid[:, None]`（完整设计矩阵）；同时输出
  `t_alpha_nw`/`se_alpha_nw` 与 `t_alpha_hc`/`se_alpha_hc`，标签各自如实；
  `np.diag` 截零后再开方（NW 的 S 不保证正定，否则对角为负会产出 nan）。
- **通律**：
  **① 出现 `* 0`、`+ 0`、`# 保守起见` 这类"消掉某个已算好的量"的写法是强烈信号——
     几乎总是上层维度/口径错误的遮羞布，必须回查根因，不能保留补丁。**
  **② 统计量标签必须随实现走：改了实现却没改名，等于给下游埋一个静默的错误判据。**
  **③ 同时保留两套口径（NW 与 HC）比二选一更能暴露问题——
     本例正是"两者本应不同却被迫相同"暴露了死代码。**

#### 13.4.3 ★ 第十四类静默 bug：二元判决过粗 + 表述在传递中被升级（2026-09-03 用户质疑触发）

**触发**：用户质疑「数据质量问题怎么会**导致无法回测**？最多就是回测不理想才对吧？」——
该质疑成立，且暴露了两处缺陷（技术一处、流程一处）。

**缺陷一（技术）：`verdict` 二元判决把两种性质完全不同的问题混为一谈。**
原判据 `PASS if n_hfq_over <= n_raw_over+1 else FAIL`，只要超限天数多就判 FAIL。
实测 600416 的四项证据：

| 检验 | 结果 | 含义 |
|---|---|---|
| 超限幅度分布 | 42 天**全部**落在 10.51%~11.82%，无一超 15% | **复权因子精度误差**，非数据错误 |
| 20 日动量信号污染 | `corr(raw,hfq)=0.9995`，`sd(Δ)/sd(raw)=8.95%` | 信号层污染有限 |
| EIV 衰减 λ | **0.852** | 效应被**稀释** → 偏保守（易假阴性） |
| 偏差序列结构 | Ljung-Box(10)=46.2 > 18.3，lag1/2/3/7 显著；超限时聚（2020 年 12 天 ≈ 期望 6 倍） | **非纯 iid** — 这是唯一支持谨慎的证据 |

⇒ 正确结论是「**回测效应被稀释、结果偏保守、易假阴性**」，而**不是「不可回测」**。
iid 噪声在因子端只产生 errors-in-variables 向 0 衰减，**不会凭空制造 alpha**。

**λ 的基线（新发现，重要）**：干净股复权会剔除分红除权跳空，信号方差应**变小**，
故 **λ = var(sig_raw)/var(sig_hfq) 正常应 > 1**；实测 600519/000001/601398/000651
λ = **1.16 / 1.19 / 2.16 / 1.57**，全部 > 1。600416 的 λ=0.852 < 1 说明噪声大到
**反转了该正常效应**，实际稀释程度**大于** 0.852 的字面值。
⇒ λ<1 是比 λ 绝对值更稳健的异常判据（跨分红率不同的股票可比）。

**缺陷二（流程）：代码表述比 SOP 原文更绝对。** §13.2 原文写的是
「日频回测**改走未复权 + 自行按除权日修正**；月/年频可容忍」——**有替代方案的处置建议**；
而 `stock_diagnose.py` 的 `discipline` 字段简写成「hfq 若 FAIL 则该股不宜用于日频回测」
——**禁令，且替代方案在压缩中丢失**。从此下游只读得到「不能用」。

**处置**：
1. `verdict` 改三档 —— `PASS` / `WARN_PRECISION`（超限但幅度 ≤15%）/ `FAIL`（幅度 >15%）；
2. 新增字段 `over_max_abs_pct`、`noise_ann_pct`、`signal_dilution_lambda`、
   `usable`、`remedy`（**把 SOP 的替代方案写进产物，不再只留禁令**）；
3. `discipline` 拆清两件事：N=1 本无「回测」这回事（**原理性限制，与数据质量无关**）；
   数据质量只影响效应估计精度。二者原先被捆成一句，会让人误以为「数据修好就能回测」。
4. 回归验证：600416 → `WARN_PRECISION`（不再声称不可用）；4 只干净股**全部仍 PASS**（阈值未放松）。

- **通律**：
  **① 写「不可用 / 不能做 / 严禁」这类禁令级表述前，必须能指出它导致的
      *具体失效模式*（偏倚方向、虚假信号机制）。说不出机制，就应降级为
     「精度受限 / 效应被稀释 / 结果偏保守」——这是可量化的，而「不可用」不是。**
  **② 表述在"文档 → 代码字段"的传递中会被压缩，而压缩方向总是*更绝对*
     （处置建议被丢，禁令被留）。凡代码里写限定的，必须回查源文档是否给了替代方案。**
  **③ 二元判决若两档的*失效模式不同*（精度误差 vs 数据错误），就必须拆档——
     否则会用同一句话描述两种后果，必然有一档是错的。**
  **④ 衡量"污染程度"必须先看*该指标在正常样本上的基线*。
     λ=0.85 单看像"稀释 15%"，但基线是 >1，实际偏离远大于字面值。**

#### 13.4.4 ★ 数据质量的影响边界：主张成立，但"结论无效"不成立（2026-09-03 用户质询 + 实测）

**触发**：用户主张「数据质量是量化 agent 的基石，数据都无法保证，那所有策略
和回测结论也都是无效的！！！」

**这个主张必须拆成三句分别判定**，因为它们的真伪不同：

| 命题 | 判定 | 依据 |
|---|---|---|
| ① 数据质量是前置闸门，必须先保证 | **成立** | 无条件 |
| ② 因此所有策略与回测结论都无效 | **不成立** | 见下方实测 ΔIC |
| ③ 因此应把主力投入转向数据清洗 | **不成立（危险）** | 见 §1 手段当目的，已犯三次 |

**实测一：坏数据的真实规模（`hfq_qc WHERE bad=1`，2026-09-03）**

| 池 | QC 条数 | **去重只数** | 去重坏数 | **真实坏股率** |
|---|---|---|---|---|
| 农业 `ashare_agri_hfq` | 190 | **95** | 1（600540） | **1.05%** |
| 半导体 `ashare_semi_hfq` | 158 | **79** | 3 | **3.80%** |
| 中证800 `ashare_csi800_hfq` | 797 | **780** | 22 | **2.82%** |
| 宽池 `ashare_wide_hfq` | 2064 | **1068** | 75 | **7.02%** |
| **中证800 `ashare_csi800_hfq_xq`（雪球，2026-09-06 起唯一生产源）** | **780** | **780** | **1**（600166） | **0.13%** |

> ⚠️ **上表前四行（腾讯 fqkline）已于 2026-09-06 全部标记为待替换**：跨源核对证实
> 腾讯后复权存在**系统性污染**（非随机坏股）——详见 §「数据源切换」。
> `ashare_csi800_hfq.sqlite` 已进入访问层黑名单，默认拒绝放行。
> 农业/半导体/宽池尚未用雪球重采，暂仍可用但**同属待替换**。

⚠️ **分母必须用 `COUNT(DISTINCT code)`，不能用 `COUNT(*)`**：
`hfq_qc` 表**无主键约束**，重复采集会插入重复行（农业池 190 条实为 95 只 ×2；
宽池 2064 条实为 1068 只 ×2）。用 `COUNT(*)` 当分母会把坏股率**系统性低估约一半**
（曾据此报出 0.5%/1.9%/5.4%，实为 1.05%/3.80%/7.02%）。
下游用 `set()` 取坏代码集合故计算结果无误，**错的只是汇报时的分母**。

极端案例真实存在且很严重：**600595 有 249 天超限、单日最大 +2150%**。
⇒ 用户的担心不是空穴来风，但它是**尾部风险**，不是全局污染。

**实测二：剔除坏数据到底改不改变结论（`ashare_qc_impact.py`，同一数据同一因子对照）**

| 池 | 坏占比 | 含坏数据 IC / t(NW) | 剔除后 IC / t(NW) | ΔIC |
|---|---|---|---|---|
| 中证800（67 期） | 2.82% | −0.0228 / −1.11 | −0.0218 / −1.08 | **0.0010** |
| 宽池（55 期） | 7.02% | −0.0216 / −1.11 | −0.0189 / −0.98 | **0.0026** |

**判定完全一致：两个池、剔除前后都是「不显著」**。ΔIC 量级 0.001~0.003，
而效应本身 0.019~0.022 —— 影响存在但**不足以翻转任何结论**。
⇒ 「所有结论无效」是过度声明。正确表述是「结论对 2.8%~7% 的样本污染稳健」。

**实测三（最贴近真实回测）：农业池 QC 闸门开 / 关对照**（2026-09-03）
同一库、同一参数，仅切换闸门（`--no-qc`），95 只池剔 1 只（600540）：

| | 可交易单元占比 | 280 项可比指标变化 | 最大 t 值差异 | **第三关判定翻转** |
|---|---|---|---|---|
| 闸门开（剔除 600540） | 78.9% | — | — | — |
| 闸门关（含 600540） | 79.9% | **269 项（96%）数值改变** | 0.37 | **0 个** |

⇒ **★ 关键区分：数值会变，判定不变。** 剔 1 只会让分位组合整体重排，
所以**几乎所有指标数值都会动**（96%）——但这**不等于结论改变**。
**评估数据质量影响必须看"判定是否翻转"，不能看"数值变了多少"**；
只看数值变化幅度会得出"数据质量毁掉一切"的错误印象。

**实测四：本项目结题结论的瓶颈不是数据质量，是样本量。**
CSI800 基本面（`equity_ic_fundamental_20260901.json`）：**n=10 期**，逐期 IC =
+0.127 / +0.043 / −0.035 / −0.050 / −0.165 / **−0.496** / +0.060 / **+0.318** / −0.242 / −0.035，
mean=−0.047，t=−0.68。IC 在 ±0.5 区间跳动 → se≈0.08 → **MDE≈0.22**，
而现实效应区间只有 0.03~0.11 ⇒ **功效不足（信息性零结果）**。
**数据 100% 干净也照样测不出来。** 把这类结论归因于数据质量，会误导后续投入方向。

#### 13.4.5 ★ 第十五类静默 bug：QC 表读不到时静默放行全部数据

**形态**（`ashare_agri_backtest.py` / `ashare_fund_backtest.py` 原写法）：

```python
try:
    qc_bad = {r[0] for r in conn.execute("SELECT code FROM hfq_qc WHERE bad = 1")}
except sqlite3.OperationalError:
    qc_bad = set()          # ← 库选错/表改名/表缺失 → 不过滤，且不报错
```

**这才是"数据无法保证"真正会发生的地方**：不是判据不准，而是**闸门被绕过且无痕**。
跑出来的结论看不出有没有过质检，事后无法追溯。

**修法不是逐个脚本补 SQL**（下次还会有第二个脚本漏），而是**闸门下沉到数据层**：
新建 `ashare_hfq_access.py` 作为后复权行情的唯一入口，三条硬纪律：
1. `apply_qc=True` 是默认值；显式关闭须加 `--no-qc` 并在报告写 `qc_applied: false`；
2. **QC 表缺失 = 数据未质检 = 拒绝放行**（抛 `QcMissing`），绝不退化成全量放行；
3. 返回对象带 `n_bad` / `bad_codes` / `qc_source`，**任何结论都能回答"剔了几只、为什么剔"**。

**已接入**：`ashare_agri_validate.py`（**原为 A 股在役链路上唯一真实漏网脚本**，
此前完全没有 QC 过滤）、`ashare_agri_backtest.py`、`ashare_fund_backtest.py`。
回归：`verify_qc_gate.py`（T1 导入 / T2 fail-loud / T3 正常读取 / T4 剔除留痕 / T5 新股）。

**排查覆盖结论**：`equity_layer_backtest.py` / `equity_quant.py` /

`daily_quotes`）→ 属「找 alpha」已冻结的港股线（**判死=禁交易信号，港股数据照常采**，见 §〇），不影响在役 A 股结论。已核实，不需修。

#### 13.4.6 极端单日收益的鉴别：市场事实 ≠ 数据错误

实测中碰到的两个"假警报"，判据是**能否用交易规则解释**：

| 案例 | 单日 | 判定 | 依据 |
|---|---|---|---|
| 688615 2024-09-30 | **+96.0%** | **市场事实**，不是错误 | 科创板新股**上市前 5 日不设涨跌幅**；该股序列首日 2024-09-26，事发第 3 日 |
| 300475 / 688629 等一批 | ±20.0% | 市场事实 | 创业/科创板涨停板 |
| 001221 2025-07-31 | −24.8% | 次新股，需个案核 | 主板次新股，仅 1 只 |

⇒ **做日频因子时必须剔除上市前 N 日**（`load_hfq_panel(drop_first_n_days=5)`）：
实测 688615 剔除前 5 日后最大单日从 **96.0% → 16.4%**。
**误把市场事实当数据错误会误杀样本；误把数据错误当市场事实会让坏数据进回测 ——
二者都要靠"能否用交易规则解释"来鉴别，不能靠绝对值阈值一刀切。**

**另注**：`board_of()` 的板块前缀已覆盖 300/301/302/688/689（±20%）、
920/430/83/87/92（北交所 ±30%）、200/900（B 股）→ **无需修改**。
（曾怀疑 689009 被误判，核查后确认：其全序列最大 23.64%、超限 14 天，判 bad 正确。）

- **通律**：
  **① 主张"数据质量决定一切"时，必须先测*影响量级*（ΔIC/Δ收益/Δ判定），
     而不是只陈述*存在性*。存在性成立 ≠ 影响显著。**
  **①′ 影响量级要测"判定是否翻转"，不是"数值变了多少" —— 前者才是结论，
     后者在分位组合重排时必然变化（实测 96% 指标变动但 0 个判定翻转）。**
  **①″ 统计分母必须去重：`hfq_qc` 无主键，重复采集产生重复行，
     用 `COUNT(*)` 会把坏股率低估约一半。**
  **② 真正的风险不在判据不准，而在闸门被绕过且无痕 —— 所有"读不到就跳过"的
     except 分支都必须改成 fail-loud，或至少在产物里留痕。**
  **③ 门禁若靠"每个消费者自觉写一遍"，必然会漏。修法是把门禁下沉到共享数据层，
     而不是去补第 N 个漏网脚本。**
  **④ 极端值的鉴别标准是"能否用交易规则解释"，不是绝对值大小。**

#### 13.4.7 ★ 第十八类静默 bug：产物文件名不随输入变化 ⇒ 跨池互相覆盖（2026-09-03 实测事故）

**事故经过**：为验证坑⑮ 的修复，按默认参数跑了一次 `ashare_agri_backtest.py`。
跑之前**确实查了输出路径**（`OUT_DIR / "ashare_agri_backtest.json"`），并据此认为
"这是农业池的产物，重跑只是刷新"——**结果它不是**。
该文件 `db_snapshot` 字段是 `ashare_semi_hfq.sqlite`（**半导体池，79 只**），
即它是用 `--db` 指向半导体池跑出来的，却占用了农业池的文件名。
本次农业池运行（95 只）把它**静默覆盖**。已用备份 `agri_backtest_BEFORE.json` 恢复。

**根因**：`out = OUT_DIR / "ashare_agri_backtest.json"` 硬编码，**不随 `--db` 变化**。
同一脚本支持 `--db` 切换标的池，却不把池写进产物名 ⇒ 不同池的结论共用同一个落点。
`ashare_agri_validate.py`（`args.out or "ashare_agri_validate.json"`）与
`ashare_fund_backtest.py`（只带 `h{holding}`，不带 `price_db`）**同病**。

**修复**（三个脚本统一原则：**产物名必须包含区分不同输入的标识**）：
- 默认库保持原名（兼容既有引用），**非默认库自动加 `_{db.stem}` 后缀**；
- 三者均支持 `--out` 显式指定路径；
- `fund_backtest` 文件名并入 `price_db` 库名（旧产物保留不删）。

**为什么"跑之前查了输出路径"仍然中招**——这才是最该记的一点：
**文件名只说明"它叫什么"，不说明"它是用什么跑出来的"。** 判断会不会覆盖，
必须比对**产物内部记录的输入标识**（本例 `db_snapshot` / `panel.tickers`）
与本次运行是否一致，光看文件名无效。

- **通律**：
  **① 产物文件名必须包含能区分不同输入的标识（库名/池名/参数），
     否则同一脚本换输入运行就是一次静默覆盖。**
  **② 回归/重跑前，核对的是产物里的 `db_snapshot`（或等价输入指纹），
     不是文件名；二者不一致即视为会覆盖。**
  **③ 脚本若支持 `--db`/`--price-db` 这类切换数据源的参数，
     就必须同步支持 `--out`，否则等于把覆盖权交给默认值。**

#### 13.4.8 第十九类：argparse help 里的裸 `%` 让 `--help` 崩溃（正常运行不触发）

`ashare_agri_backtest.py` 原有 `help="…涨幅≥9.5%的股票…"`。
argparse 会对 help 做 `%` 展开（`_expand_help`），`%的` 被当作格式符
⇒ `--help` 抛 `ValueError: unsupported format character '?' (0x7684)`。

**它只在 `--help` 路径上崩溃，正常运行完全不触发** —— 所以跑了无数次回测都没发现，
直到本次做改动后回归验证时才暴露。修法：含 `%` 的 help 一律写 `%%`。

- **通律：改完脚本，回归至少要跑一次 `--help` 和一次真实运行 ——
  二者走的是不同代码路径，只跑其一会有整类错误看不见。**

#### 13.4.9 第二十类：`signal_dilution_lambda` 的表述在 λ>1 时语义反号（2026-09-03，688615 诊断时发现）

`stock_diagnose.py` 原固定输出「20日动量信号稀释 lambda={lam}（**效应低估 {(1-lam)*100}%**）」。
**λ=1.184 时打印出「效应低估 -18%」** —— 语义荒谬（负的低估 = 高估？）。

**根因（与坑⑭ 同族）**：λ>1（**正常**：复权剔除除权跳空使信号方差变小，干净股基线 1.16~2.16）
与 λ<1（**异常**：噪声大到反转该效应）**语义相反**，却共用同一句模板 ⇒ 必然有一档是错的。

**修法**：按 λ 是否 ≥1 分档输出——
- λ≥1：`属正常区间（干净股基线 1.16~2.16；复权剔除除权跳空使信号方差变小）`
- λ<1：`**异常**：噪声大到反转了上述正常效应，20日动量被稀释约 X%，回测易假阴性`

**验证**：688615 λ=1.184 → 「≥1 属正常区间」✓；600416 λ=0.852 → 「<1 异常，稀释约 15%」✓。

⇒ **§13.4.3 通律③ 已被触发两次（坑⑭ 的 PASS/WARN/FAIL、坑⑳ 的 λ≥1/<1）。
凡"同一个指标在两侧区间含义相反"，必须拆档输出，不得共用模板。**

**顺带验证（好消息）**：688615（科创板次新，上市第 3 日 **+96.0%**）经 `stock_diagnose.py`
诊断为 **PASS**，未误判为数据错误 —— 因为判据是 **raw/hfq 超限天数对照**（5 天 vs 3 天），
新股无涨跌幅限制在 raw 与 hfq 上**同样存在**，对照后自然抵消；**不是靠绝对阈值**。
这条设计经受住了检验，**不要"顺手"改成绝对幅度阈值**，那会误杀全部次新股。

#### 13.4.10 ★ 反例留档：「第廿一类静默 bug（EXIT trap 吞掉退出码）」已实测证伪（2026-09-03）

**这一节记录的不是 bug，是一次错误的 bug 定案。留档价值高于 bug 本身。**

**原指控**：`run_dsh_agent.sh` 的 EXIT trap 末条 `[ -d ... ] && echo ... || true` 恒定返回 0，
会覆盖 `exit "$RC"` ⇒ node 失败时脚本仍以 0 退出，外层调度/CI 看不出异常。
**依据的现象**：日志打印 `exit=0`，外层任务却报 failed。

**做了什么（错在哪）**：**没做最小复现**就据此改了代码、写进 SOP、写进日志，
并升格为通律「EXIT trap 必须保存并显式回传退出码」。

**最小复现结果（三对照，`_verify/trap_rc_test.sh` 忠实复刻脚本结构：`set -euo pipefail`
+ `set +e` + `exit "$RC"`）**：

| 模式 | 外层退出码 |
|---|---|
| 无 trap | **7** ✓ |
| 旧 trap（`... \|\| true`） | **7** ✓ |
| 新 trap（`rc=$?; ...; exit $rc`） | **7** ✓ |

⇒ **三种写法都正确回传，指控不成立。**

**真实机理（边界枚举）**：

| 情形 | 外层退出码 | 说明 |
|---|---|---|
| 显式 `exit 7` + trap 末条成功 | 7 | trap **不覆盖**显式 exit |
| 落尾退出（`false` 后无 exit）+ trap 末条成功 | 1 | 同上 |
| `set -e` 触发 + trap 末条成功 | 1 | 同上 |
| 显式 `exit 7` + **trap 内自己 `exit 0`** | **0** | ← **唯一真会吞掉退出码的情形** |

**结论**：bash 的 EXIT trap **不会**改变已确定的退出状态；**只有 trap 内部显式调用 `exit` 才会**。
旧代码没有 trap 内 exit ⇒ 无此 bug。新写法的 `rc=$?; ...; exit $rc` 属无害的显式化，予以保留，
但**不得再以「修复吞退出码」的名义复述**（脚本内注释已同步更正）。

**原始现象仍待查**：「日志 exit=0 而外层报 failed」**原因未确定**。既然退出码传递经实测可靠，
该现象更可能来自外层调用链（并发/后台任务状态判定/督导逻辑），**与脚本无关**。
⇒ **不得用未经验证的机制去解释未解释的现象**。

**★ 通律（本项目高发，与坑⑮ 同源但方向相反）**：
**机理型结论（「因为 X 机制，所以 Y 结果」）必须先跑最小对照实验再入册。**
本项目已积累 20 类真静默 bug，容易形成「看到异常 → 套一个合理机制 → 当成第 N+1 类」的惯性；
但**越是贴着既有分类的假说，越要用对照实验证伪它**。现象解释不了时，
如实记「原因待查」，**不要用听起来合理的机制填补空白** ——
一个被写进 SOP 的错误机理，比一个未解释的现象危害更大。

**实测结果**：

| 池宽 | MDE(10年) | MDE(13年) | vs 农业池效应 0.111 | vs CSI800 效应 0.0314 |
|---|---|---|---|---|
| **27（电机Ⅱ/Ⅲ 实际值）** | 0.1572 | 0.1378 | 0.71 / **0.81 ✗** | 0.20 / 0.23 ✗ |
| 50（原提议） | 0.1327 | 0.1164 | 0.84 / **0.95 ✗** | 0.24 / 0.27 ✗ |
| 80 | 0.1208 | 0.1059 | 0.92 / 1.05 ✓ | 0.26 / 0.30 ✗ |
| 300 | 0.1045 | 0.0917 | 1.06 / 1.21 ✓ | 0.30 / 0.34 ✗ |

**三条判定**：

1. **27 只（湘电股份的精确同类池，申万电机Ⅱ/Ⅲ 实测 27 只）在功效上完全不可行** ——
   13 年 MDE 0.1378，**即使效应量达到农业池那个唯一成功案例的水平（0.111）也测不出**
   （比值 0.81 < 1）。且 27 只含次新股，真实 N_eff 只会更小。
2. **原提议的"≥50 只"同样是错的** —— 13 年下比值 0.95，仍然 < 1。
   检出农业池量级效应的最低门槛是 **13 年 ≥63 只 / 10 年 ≥147 只**。
3. **现实基准（CSI800 同因子量级 0.0314）在任何可达配置下都测不出**
   —— 4000 只以内无解。而 CSI800 换池实验已证明：**净利同比在非农业板块就是这个量级**。

**结论分类**：**信息性零结果（结构性的）** —— 不是"这个池可能有信号没测出来"，
而是"这个配置下**不可能**测出来"。已判死，不得重复投入。

> ⚠️ **措辞纪律**：这是「功效不足」与「已证伪」的**叠加**，二者必须分开陈述：
> ① 池太窄导致测不出（功效不足，结构性的，扩池可缓解但门槛远高于直觉）；
> ② 因子本身在非农业板块已被 CSI800 证伪（已证伪，扩池无用）。
> 任意一条单独成立即足以否决建池。

**通用教训（适用于任何"为某个标的建专属窄池"的提议）**：
`MDE` 的主导变量是 `N_eff`（期数），不是截面宽度；窄池的统计代价虽不如直觉大，
但**当池宽 < 80 时，Var_noise 开始主导 σ_obs，MDE 被推到 0.10 以上** ——
而 A 股基本面因子的现实效应量只有 0.03~0.11。**窄池 + 基本面 = 结构性测不出。**

#### 14.6.1 ★ 第廿二类静默 bug：QLIKE 的"削减率"比值公式在损失可为负时符号翻转

**现象**：MSE 降 11.87%，但 QLIKE 报 **−3.10%（恶化）**。QLIKE 才是波动率的标准损失，
而"低估高波动"恰恰是回撤预警最怕的失效模式 ⇒ 必须先查清。

**我的排查链（三层，前两层都错，记录在此以警示）**：
1. 第一假设"偏差修正共用 persistence 的 s² 写错了" → 改成各模型用自己的训练残差方差。
   结果 −3.23% → −3.10%，**几乎没动 ⇒ 假设被证伪**。
2. 我据此写下"**恶化是真实的**"，加分桶诊断定位。分桶结果：模型在**每一档都赢**
   （QLIKE_M < QLIKE_P 五档全中）⇒ 与我"恶化是真的"判断直接冲突 ⇒ 还有第三层原因。
3. **最小对照实验**（`outputs/2026-09-04/_verify/qlike_check.py`，已知真值可解析求最优）：

| 检查项 | 结果 |
|---|---|
| `q = log(v̂²)+v²/v̂²` 与标准 QLIKE 的**差值** | 完全一致（+0.223545 vs +0.223545）⇒ 分桶比较是对的 |
| 两者关系 | `q = QLIKE_std + log(v²) + 1`，平移项**只依赖已实现值** |
| `q` 的取值 | **可为负**（实测 −3.198） |
| `1 − mean_m/mean_p`（分母为负） | **−7.51%**，把真实改进 **+27.16%** 符号翻反 |
| 偏差修正指数扫描（解析最优 k*=2） | 数值最优 **k=2.0** ✅；我用的 `corr=exp(s²/2)` 平方后只给 `exp(s²)` ⇒ **k=1 欠修正** |
| k=1 的后果 | **夸大**残差更小那个模型的 QLIKE 优势（gap −0.0419 vs 正确 −0.0213）|

**修正**：改用标准非负 QLIKE `v²/v̂² − log(v²/v̂²) − 1`（≥0，等号 iff v̂²=v²），
偏差修正取 `E[RV²|info] = exp(2ŷ + 2s²)`。修正后 QLIKE 降低 **+24.4%~+38.9%**，
与 MSE **同号**，且新增的 QLIKE 口径 NW-DM 也 p≈0（见上表末列）。

**通律（三条）**：
1. **"相对改进 %"这类派生指标，必须先确认分母非负且零点有意义。**
   MSE/QLIKE_std 满足；平移过的损失、IC、夏普差值等**不一定**满足。
2. **从一种域复制公式到另一种域，其前置条件要逐条复查。**
   与第十类（`"可交付" in "真实但不可交付"`）同族：都是"字符串/公式跨语境复用而前置条件失效"。
3. **假设被证伪后，不要停在"那恶化是真的"。**
   若两个口径给出相反结论，说明**至少还有一个未识别的原因**，必须继续查到两者自洽为止。

### 14.7 关卡③：经济可行性（脚本 `ashare_vol_targeting.py`）

**组合**（块频；敞口 `w=clip(target/σ̂, 0, 1.0)`：**不加杠杆、不可做空**；现金收益 0，保守）：
`EQ` 等权满仓 ／ `VT_BP`/`VT_B` 篮子层择时（σ̂ 预测**等权篮子自身**波动）／
`VT_P`/`VT_M` 个股中位数波动择时（控制对象有缺陷，见下）／ `IV_P`/`IV_M` 个股层逆波动加权。

**★ 检验方法：波动匹配后的均值检验。**
直接比**绝对收益**必然吃亏（VT 降低了波动）；直接比 **Sharpe** 又无法做 DM 推断。
解法：把 A 按 `s = sd(B)/sd(A)` 放大到与 B 同波动，对 `d_t = s·r_A,t − r_B,t` 做 NW(HAC) 单侧检验。
**这在数学上等价于比较 Sharpe，但可做推断。**
⚠️ **诚实边界**：放大仓位需要加杠杆，A 股散户难以实现 ⇒ 若 Sharpe 提升而绝对收益下降，
正确交付语义是**风险/回撤下降**，不是"收益提高"。

**判据**：NW p≤0.10 且 |效应|/MDE≥1 且 逐年为正≥60%。
**预注册主检验 1 条**：★VT_B vs EQ。其余为二级，只用于定位增量来自哪一层。

#### 14.7.1 ★ 第廿三~廿六类静默 bug（回测口径四处不一致，全部我自己写的）

| # | 机制 | 实测后果 |
|---|---|---|
| **㉓** | **persistence 基准未滞后**：`L[:,t]` 是第 t 块的已实现波动（**块末才可知**），却与第 t 块收益同索引；模型侧 `Yh[:,t]` 用的是 t−1 信息 ⇒ **两侧信息集不对称 = 前视** | IV_M vs IV_P 从 **+8.72%（p≈0，r=5.71）塌到 +0.36%（p=0.07，r=0.52）** |

### 14.8 ★ 方向 1 结论：统计算出大胜，经济上等于零（2026-09-04 判死）

|---|---|---|---|

叠加 A 股不可做空、不加杠杆（cap=1.0 ⇒ 择时只能减仓），
在 2014-2026 这段净上涨样本里减仓天然吃亏。

**⇒ 波动率择时在 A 股等权篮子（周/月/季调仓、不加杠杆）上不成立，方向 1 判死，勿重开。**

**残留的"可能"与它为什么也不能交付**：
h=5 上 VT_B 把**最大回撤从 43.29% 压到 32.00%（−11.3pp）**，是唯一方向为正的一项。
但 |效应|/MDE=0.31 ⇒ 要把 MDE 从 5.52% 压到效应量 1.70%，
需 `n' = 574 × (5.52/1.70)² ≈ 6,056` 期 ≈ **120 年数据** ⇒ **结构性测不出**。

**留存的资产（不是策略，是方法与判据）**：
1. **关卡①的对比基准**：波动率预测的 \|效应\|/MDE=1.87~5.22 vs 收益率预测的 IC 0.01~0.11 / MDE 0.10+
   ⇒ 今后判断"哪类目标值得测"，可以直接套这个量级对照。
2. **横截面相关 ⇒ 先聚合到每期再检验**的推断口径（§14.4②），以及**波动匹配后的均值检验**
   （= 比较 Sharpe 的可推断版本）——两者都是可复用的统计工具。
3. **"统计显著 → 经济可行"的衰减链条**（上表）——今后任何新信号，
   在宣告成功前必须走完这三关，不许在关卡②就收工。

### 14.9 方向 2 现在是唯一剩下的路（论证）

方向 1 换了**目标**（收益 → 风险），但**信息源没换**（仍是后复权价量）。
结果：目标换对了（功效从"测不出"变成 1.87~5.22），但**仍然交付不了**。

这与 §3 的根因诊断一致：**5 个价量因子全是同一信息源的线性变换 ⇒ 风格假人是必然，不是运气**。
方向 1 证明了**在同一信息源内换目标也不足以救** ⇒
**⇒ 剩下的唯一变量是信息源本身：方向 2（落库另类数据）是必答题，不是选答题。**

未消除的 caveat（如实记录，不因结论为负就省略）：
- **幸存者偏差**：CSI800 是 2026-09-02 成分快照回看 2014。已用 `--since 2019-01-02`
  做敏感性（**结论方向不变**）。差分类检验（VT/IV 各自 vs 同一个 EQ）对此**大部分免疫**，

- **只测了一个等权篮子**，未测宽基指数：Moreira-Muir 的经典结果建立在**指数**上。
  但腾讯行情 **641 根硬上限**（≈2.6 年）⇒ **现有数据无法对指数做充分检验**，这是硬的数据限制。

- **A/B 对照前必须先用旧源复现基线**。漏加 `--exclude-financial` 会让 PB 截面多 52 只金融股
  （557→609），若未复现基线就会被误读成「数据源差异」。复现结果：gm_change 逐位一致（1.035）、
  PB 逐位一致（0.489）、rev_yoy 差 0.8%。
- **别把未验证的机理当结论**。曾推断「PB 是方向性偏差 ⇒ −0.0277 不可信」，实测 IC 仅变到 −0.0266（4%），
  **担忧未证实**。听起来合理的机理仍是猜测，必须实测。

## 十七、静默 bug 续（第卅~卅一类，2026-09-06 案例对撞新增）

### 第卅类 · 「由标识派生标识」的拼接规则必须跨样本实测
巨潮公告 `orgId` 曾按「代码前缀 + 代码」拼：`6`→`gssh0{code}`、`8/4`→`gsbj0{code}`、其余→`gssz0{code}`。
实测四种情形：

| 代码 | 真实 orgId | 旧规则拼接 | 结果 |
|---|---|---|---|
| 600927 | `gfbj0833840` | `gssh0600927` | ✗ 0 条 |
| 600519 | `gssh0600519` | `gssh0600519` | ✓ 碰巧对 |
| 000001 | `gssz0000001` | `gssz0000001` | ✓ 碰巧对 |
| 300413 | `9900023257` | `gssz0300413` | ✗ 0 条 |

orgId 是巨潮**内部公司 ID，不能由证券代码逆推**（且格式本身有 4 种变体）。
**通律：凡是「由 A 标识拼出 B 标识」的规则，必须先跨 ≥4 个不同前缀/类别样本实测，
再写进代码。**「两个样本对了」不构成验证——这正是「碰巧正确」的第 N 次出现。
**修法三层**：① 优先调官方反查接口（`topSearch/query`）拿真实 ID；
② 反查失败才回退拼接，并在产物打 `org_id_fallback=True` 标记；
③ 加**零结果自检**——参数看似正确却 0 条时输出 `note` 提示「疑似参数问题」。

### 第卅一类 · 批判开源之前，先自查是否正在犯同一个毛病
本轮在文档里批判 TradingAgents「静默失败、v0.2.5 才从幻觉编造改成读真新闻」，
**而自己的 `ashare_evidence.py` 公告层正把「参数拼错导致零结果」报成 `EMPTY`**
（明明刚立过「`EMPTY`确实没有 ≠ `UNAVAILABLE`没拉到」的规矩）。
**通律：拿真实案例输出去撞，而不是拿别人的文档去抄。** 只读文档会强化「我已理解」的错觉，
实跑案例才会暴露自己。案例对撞的真正价值在这里。

### 相关通律（同批产生）
- **结论 ↔ 证据必须绑定**：开源 TradingAgents 有 `supporting_evidence` 字段，
  我方原实现 [5] 结论段与 [6] 证据段两张皮。补法是关键词命中提示，
  措辞固定为「含「X」字样，可能关联 *Y*（系统匹配，需人工核实）」——**只提示不推断**。
- **回撤归因必须有起点**：原实现只算幅度（`-75.8%`）不算高点日期 ⇒ 无法回答「这段时间发生了什么」。
  补法：记录高点日期 + 持续交易日数，再按时序列出窗口内公开披露。
  护栏：① 明写「是**时序对齐，不是因果推断**」；② 窗口 >250 日时追加覆盖提示，
  **自曝「证据远非窗口全貌」**，不许假装完整。

## 十八、清理/删除操作纪律（第卅二类，2026-09-06 冗余清理新增）

### 第卅二类 · 删文件前两条前置检查

实测：`scripts/macro-analysis/` 下 7 个孤立脚本中**只有 1 个被 git 跟踪**，

**② 「0 引用」≠「冗余」。**
判据必须是两条**同时**成立：①全仓 0 代码引用；②所属方向已关闭。
反例（差点误删）：
- `ashare_xq_qc_compat.py`：0 引用，但是**当天新建**的雪球 QC 兼容层，属在用工具链 ⇒ 保留。
- 一次性采集器（如 `wide_liquidity`）、独立 CLI 入口本来就不被 import ⇒ 0 引用属正常。

### 相关通律：引用检查必须跨目录
第一版只在 `scripts/macro-analysis/` 内 grep 就得出「0 引用」——**这是自检路径 ≠ 生产路径的又一次变体**。
`workflow.md` 在 `packages/preset/` 下，是 agent 的「大脑」，**可能以自然语言指令调用某脚本**；
只在代码目录内 grep 会漏判。必须全仓扫 `.py/.sh/.yml/.md/.mjs`。

## 十九、第卅五类：增量模式污染断点续采表（2026-09-06 审计发现）

**形态**：采集器同时支持「code 粒度断点续采」（`already_done(key=code)`）与
「日期级增量」（`--since`）。增量模式只拉了 `date >= since` 的**片段**，却仍调用
`log_done(code)` 把该 code 标记为「已采」。日后想全量重采时，`already_done` 全命中
⇒ **全部跳过，数据永久残缺，且不报错**。

**危害**：静默、不可逆（除非手动清 `collect_log_*`）。日采跑得越久，污染越彻底。

**修法**：增量模式**不写**断点续采表（只写业务表，靠 `INSERT OR REPLACE` 幂等）：
```python
if not since:          # 只有全量模式才记断点
    log_done(conn, "margin", key, len(recs))
```
**通律**：一个 key 空间只能表示一种语义。断点表记「已全量采过」，增量就别往里写。
已在 `ashare_altdata_collect.py` 的 margin / block / lift 三处同时修复。

## 二十、第卅六类：默认参数 = 数据边界（2026-09-06 判决书数据陈旧事故）

**形态**：采集器的**时间边界参数取硬编码默认值**（`--end-year default=2025`），
跨年后 2026 年的报告期永不进入 `periods` 列表 ⇒ 库停在 2025-12-31，**静默无报错**。

**为什么致命**：`ashare_risk_verdict.py` 的 `label_agri_np_yoy` 取
`ORDER BY report_date DESC LIMIT 1` ⇒ 一直拿到 18 个月前的年报打风险标签。
补采后实测：农业池 95 只中 **47 只（49.5%）标签翻转**，NORMAL 60→45、COLLAPSE 15→30。
**「数据已更新」的报告掩盖了「下游判定过半是错的」这一事实。**

**修法**：时间边界默认取动态值（`default=date.today().year`）。
空期（未到披露期）记 `status='empty'`，`--resume` 只跳 `'ok'` ⇒ 会持续重试，安全。

**识别通律（与第卅三类同源：默认值是数据销毁开关）**：
凡是「默认值会**缩小**采集范围」的参数（年份上界、count 条数、日期下界），
都是高危项；凡是「默认值扩大范围」的（多采一些）只会慢，不会丢数据。
⇒ 代码审查时优先扫**上界/条数类**参数的默认值。
